# L6 Performance audit

Stack: Next.js 16.4.0 (Turbopack), React 19.3, wagmi 2 / RainbowKit 2 / viem, Supabase (server-side), TanStack Query. Mode: Deep for bundle numbers (production build in ext4 copy, `/home/alexheiz/.claude/jobs/05f8a858/tmp/scratch/.next`), source-only for everything else. No field data (CrUX) and no Lighthouse run, so no LCP/INP/CLS values are claimed; CLS/LCP items are `potential impact`.

Method for sizes: sum of gzip (zlib level 6) over every `<script src>` in the prerendered `server/app/<route>.html` (excluding the `noModule` polyfill chunk). Brotli would be about 15 percent smaller, which does not change any conclusion. `/` and `/q/[id]` are dynamic (no HTML in build output); the client-reference manifest lists 308 kB vs 293 kB for `/contest`, so they are inferred at roughly +15 kB over the static routes.

## Verified non-issues / positives

- Fonts: single `next/font/google` JetBrains Mono, `display: swap`, self-hosted woff2, one preloaded (`70bc3e132a0a741e-s.p...woff2`, 40 kB); body font is a system stack (`globals.css:24`). No font shift risk beyond swap.
- Images: no `<img>`/`next/image` usage; only `icon.svg` and the three mp3 files in `public/`. Nothing to optimise.
- Wallet connector SDKs (coinbase, metamask, walletconnect) are already in lazy chunks, not in the first-load set; `@google/genai` and `@supabase/supabase-js` are server-only; all seven quiz modals and `AuthPopup` use `next/dynamic`.
- Leaderboard polling is gated: `LeaderboardPanel.tsx:32` IntersectionObserver feeds `refetchInterval: isLeaderboardVisible ? 15000 : false`; TanStack Query also pauses intervals in background tabs by default. Quiz timer interval (use-quiz-logic.ts:285) is correctly cleaned up. `ListCard.tsx:55` 60 s interval is trivial.
- SSR for `/` fetches question and leaderboard in `Promise.all` (`app/page.tsx:23-26`), and `/q/[id]` does likewise, so no sequential waterfall at the server.
- Static shells for `/contest`, `/my-lists`, `/review`, `/profile` prerender; content loads client-side.
- Aggregation is done in Postgres functions, not by streaming raw rows to Node; `search_questions` has trigram GIN indexes (`search.sql:6-7`).
