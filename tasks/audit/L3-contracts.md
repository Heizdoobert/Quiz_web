## Verified OK (no finding)
- Reentrancy: `createContest`, `claimReward`, `refundRemaining` are `nonReentrant` and follow checks-effects-interactions (nonce set and pool decremented before `safeTransfer`; ContestEscrow.sol:121-127,146-150).
- SafeERC20 used for all transfers; ECDSA.recover from OZ 5.6.1 rejects high-s and zero-address recovery; signature malleability does not bypass nonce check (nonce is keyed on struct fields).
- EIP-712: domain includes name/version/chainId/verifyingContract via OZ `EIP712`; struct binds contestId+recipient+amount+nonce+deadline; client and server types match contract typehash (ContestEscrow.sol:21-22 vs question-list-actions.ts:973-983).
- Nonce: 128-bit random (`crypto.randomUUID`, chain.ts:23), per (contest, recipient); vouchers expire <=1h and are capped to contest expiry; one open voucher per entry via partial unique index (ADR-007 point 4).
- Integer math: 0.8.24 checked arithmetic; `remainingPool -= amount` guarded by prior `amount <= remainingPool`; rewards computed with BigInt (rounding dust only).
- ABI sync: lib/contracts/*ABI.ts identical to compiled artifacts.
- `REWARD_SIGNER_PRIVATE_KEY` is server-only (`import 'server-only'` in chain.ts:1, not NEXT_PUBLIC); Dockerfile build key (0x9999...) is only in the builder stage, not the runner.
