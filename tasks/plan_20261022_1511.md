# Implementation Plan: Re‑organize `lib/actions` by functional domain (session 2026‑10‑22)

## Overview
The `lib/actions` directory has been reorganized into domain‑specific sub‑folders (`admin`, `ads`, `auth`, `community`, `quiz`, `users`). This plan records the remaining verification steps, import‑path updates, cleanup, and commit workflow.

## Architecture Decisions
- Keep each `*-actions.ts` as a thin re‑export barrel.
- Preserve the root `index.ts` that aggregates the domain folders, so external imports remain unchanged.
- Restrict changes to only the files that need import updates or header comments.

## Risks & Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| Missed import updates causing runtime errors | Build/test failures | exhaustive grep after updates |
| Stale duplicate files left behind | Confusion, dead code | explicit stray‑file removal step |
| Build breaks due to type‑errors from path changes | CI failure | run `npm run build` after each slice |

## Task List

### Phase 1 – Verify layout
- **Task 1** – Verify all expected files exist in their new locations.

### Phase 2 – Update imports
- **Task 2** – Search for old root imports of `*-actions.ts` and replace with the new domain‑folder paths.

### Phase 3 – Clean stray files
- **Task 3** – Delete any leftover files outside the domain folders (only `index.ts` should remain at the root).

### Phase 4 – Build & test verification
- **Task 4** – Run the project build (`npm run build`) and test suite (`npm test`).

### Checkpoint – After Tasks 1‑4
- All verification steps succeed.

### Phase 5 – Add header comments
- **Task 5** – Add a one‑line comment to each `*-actions.ts` indicating it is a re‑export barrel.

### Phase 6 – Commit & push
- **Task 6** – Stage, commit with a descriptive message, and push to the current branch.
