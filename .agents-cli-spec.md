# Agent Spec: GameOps Sentinel & Real-Time Telemetry Agent

## Overview
`gameops_sentinel` is a hybrid ADK agent designed to monitor, protect, and orchestrate the competitive integrity and telemetry of Quick Quiz. It operates in two complementary modes:
1. **Autonomous Anomaly Detection**: Periodically audits recent duel attempts (`quiz_attempts`) and mobile synchronization records (`answer_queue`), identifying impossible split-time anomalies (bot patterns, script runners) and sudden sync error spikes.
2. **Interactive RCM Copilot**: Embedded within the Real-time Control Module (RCM) admin dashboard, allowing operators to query recent duel health, review quarantined attempts, and trigger guided remediations.

The agent uses a **Coordinator + Dual-Specialist** architecture:
- `gameops_sentinel_coordinator`: Root agent that triages incoming admin prompts or scheduled health scans.
- `telemetry_monitor_agent`: Specialist that evaluates split-time distributions, detects anomalies, and monitors mobile queue health.
- `remediation_agent`: Specialist that soft-quarantines suspicious attempts, writes structured audit logs, and enforces Human-in-the-Loop (HITL) approval gates for destructive interventions.

## Language
`python` (Python 3.11+ using Google ADK)

## Example Use Cases

### 1. Automated Split-Time Anomaly Detection & Soft-Quarantine
- **Trigger**: Batch review of recent duel completions.
- **Input**: Attempt record with 5 questions answered in 140ms total (< 30ms per question, zero variance).
- **Execution**: `telemetry_monitor_agent` calculates an anomaly score of `0.98` (rule: `< 250ms` per question is statistically inhuman). It delegates to `remediation_agent`, which calls `soft_quarantine_attempt(attempt_id, reason="Inhuman split times (<50ms per question)")` and logs the action to `audit_logs`.
- **Expected Output**: Attempt is soft-quarantined, excluded from public leaderboards, and an incident summary is logged.

### 2. Interactive Admin Triage with Approval Gate
- **Input (from Admin)**: *"Inspect recent anomalies for user @speedy_bot and apply appropriate action."*
- **Execution**: Coordinator delegates to `telemetry_monitor_agent` to fetch attempt history, showing 4 consecutive sub-second completions. `remediation_agent` confirms soft-quarantine of the scores, but identifies that an account ban is warranted. Because an account ban is a destructive action, the agent triggers the HITL gate.
- **Expected Output**: *"User @speedy_bot has 4 confirmed bot-speed duel submissions. All 4 attempts have been soft-quarantined. Would you like to issue a 24-hour competitive ban on this account? [Confirm Ban / Dismiss]"*. The ban is not applied until explicit admin confirmation.

### 3. Mobile Offline Sync Health Check
- **Input (from Admin)**: *"Check health of the mobile sync queue."*
- **Execution**: `telemetry_monitor_agent` queries recent records in `answer_queue`, measuring failure retry counts, payload deduplication, and timestamp drift against the 24-hour grace window.
- **Expected Output**: Clean status report: *"Mobile sync queue healthy: 0 unhandled failures, error rate 0.1%, streak grace window respected across all 214 recent submissions."*

## Tools Required

1. **`fetch_recent_attempts(limit: int = 50, since_minutes: int = 60)`**:
   - *Purpose*: Retrieves recent duel attempt records from Supabase `quiz_attempts`.
   - *API & Auth*: Supabase REST API via `supabase-py` using scoped service credentials.
2. **`analyze_split_times(timestamps: list[int], question_count: int)`**:
   - *Purpose*: Calculates per-question response times, variance, and anomaly confidence score (0.0 to 1.0).
   - *API*: Pure internal computational utility.
3. **`soft_quarantine_attempt(attempt_id: str, reason: str)`**:
   - *Purpose*: Marks attempt status as `quarantined` in Supabase, hiding it from public leaderboards while retaining data for review.
   - *API & Auth*: Supabase update query.
4. **`fetch_sync_metrics(window_minutes: int = 60)`**:
   - *Purpose*: Aggregates error status and retry volume from mobile client synchronization.
   - *API & Auth*: Supabase aggregation query on `answer_queue`.
5. **`request_human_confirmation(action: str, target_id: str, details: str)`**:
   - *Purpose*: Pauses workflow execution for destructive actions (e.g., account bans, bulk score deletion) and requests admin confirmation token.
   - *Pattern*: ADK workflow pause / HITL callback.

## Constraints & Safety Rules
- **Tiered Guardrails**:
  - *Autonomous*: Can view attempt records, calculate statistical scores, flag/soft-quarantine individual attempts, and write to `audit_logs`.
  - *Gated (Requires Human Confirmation)*: Applying account bans, resetting user streaks, modifying quiz question data, or sending external notifications.
- **Credential Protection**: Supabase keys (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`) must only be read from environment variables; they must never be echoed in model responses or tool outputs.
- **Performance**: Anomaly evaluation tools must execute in $< 50\text{ms}$ to ensure zero latency overhead on high-frequency duel checks.

## Success Criteria
- **Anomaly Detection Accuracy**: 100% of simulated bot submissions ($< 250\text{ ms}$ total completion) are flagged as anomalies in eval tests.
- **Zero False-Positive Quarantines**: 100% of realistic human attempts ($> 1200\text{ ms}$ per question with natural variance) pass without quarantine.
- **HITL Enforcement**: 100% of destructive action requests (`ban_user`, `purge_scores`) trigger the confirmation gate; none execute silently.
- **Eval Benchmark**: $\ge 90\%$ pass rate on the end-to-end `agents-cli eval` suite across detection, triage, and safety scenarios.
